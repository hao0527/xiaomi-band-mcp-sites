# 当前快照的已知限制

该快照选择保留现有业务逻辑，不因开源而重构或扩大接口。以下是复现和使用时应知道的实际边界。

## 原始内容与读取

- 普通源记录在去除认证字段后存入raw_records/raw_versions。解析失败保留raw_json和schema_unverified；单条外层时间戳/来源格式异常现会进入独立隔离表，其他有效记录继续；响应封装、分页协议及隐私保护失败仍会停止。
- MCP普通明细仍返回规范化data，并新增统一record_ref/source_ref；get_raw_record可分块读取脱敏后的当前原始JSON，保留未知字符串和长数组。原始版本历史读取仍未提供，畸形外层JSON会保留在D1并因凭据安全而拒绝回传。
- 新抓取的运动operational详情同时保存脱敏完整源响应和独立展示投影，并保留源版本。旧的仅投影缓存没有被重抓或伪造为完整原文；展示投影仍有字段/深度/数组/文本限制，完整内容通过get_raw_record(component=activity_operational)读取。
- 原生运动完整解密后文件以base64保存在D1；公开读接口只输出已解码心率和有限结构信息。无效点原值及其他点字段未全部结构化返回，但仍在原文件内。

## 运动与原生曲线

- 正常增量同步会处理运动列表和有限operational详情；原生文件获取是独立的所有者授权操作，不是trigger_sync自动补齐全部运动。
- 当前解码器仅验证运动格式8、记录版本4、storage_mode=0；文件上限2MiB、点数上限21600。跑步/骑行、其他版本和压缩格式尚未移植验证。
- 正式原生每秒记录点不保证光学传感器每秒独立测量。零/无效HR不填补为正常心率。
- 未找到原生缓存时回退到运动时间范围内的全天心率采样，明确标为非原生；详情和分析最多先读2000个日常采样。超长记录可能受这个上限影响。
- 失败、空文件或checking缓存目前没有自动过期复查/租约恢复；不可声称云端晚上传文件一定会自动补齐。
- 原生分页读的是当前缓存，没有快照版本游标；查询期间若未来实现缓存替换，需要再验证分页一致性。

## 指标、来源和日期

- 采集与通用读取仍限定21类keys；不存在“已覆盖全部小米健康数据”的保证。渠道有数据、空结果、未验证与硬件能力需区分。
- HRV可从已缓存睡眠记录读取源字段；五个汇总字段单位已按所有者App对账为ms，其余单位、算法与独立逐点接口未确认，不能由心率推算。全零占位保留但不视为真实HRV零值。
- rawrecover_time、训练负荷算法、calories与total_cal范围等未完全确认；保留源值与unverified/source_reported状态。
- App步数参考与聚合策略属于各部署自己的私有D1，公开仓库不提供他人的参考值。新部署的日步数为空可能是策略未验证，不应改用多源相加。
- 当前按原始记录时间保存日期；解析后的业务归属日期与原始日期可能不同，跨日睡眠、日桶与日历边界仍需独立核验。不要为适配新账号盲改已通过的解析规则。
- 上游分页首桶语义、不同日报的秒/毫秒参数不能直接从其他项目类推；新增接口应分别验证。

## 历史、状态与费用

- 365天是本实现初始计划，不是服务端保留期限；历史没有自动向更早日期扩展，也没有已完成历史区间的无限周期重查。
- 闭合自然日、同步成功、采样新鲜、云端上传完整是不同概念；空结果不是零，完整上传通常未知。
- 通用每页2000、心率31天/次、其他90天/次是有意的查询边界；通过日期分段和游标读取，不移除上限来掩盖缺口。
- 兼容的每日摘要存在12000行上限，周报告使用已存摘要，不能替代完整原始明细。
- 源码含固定2027-01-01费用复核门限；停止采集不会自动删除平台数据或取消可能的存储费用。

## 保留兼容性

当前20项MCP中包含既有摘要/简单分析工具，它们保留兼容，不作为未来扩展重点。未来优先完整保留与读取、覆盖和同步质量，不在服务端新增恢复判断、医疗结论或复杂评分。

隔离记录保留错误原值及请求窗口，不伪造时间；get_sync_status只列最近10条引用，并非完整分页目录。新增源响应版本保留在D1，目前尚无通用历史版本读取接口。
