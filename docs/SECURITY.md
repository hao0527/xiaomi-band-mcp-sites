# 安全与公开导出边界

## 部署边界是必须条件

此Worker为**所有者唯一访问的Sites**设计。Sites在请求进入Worker前校验访问权限，MCP数据调用还要求平台传入的用户身份。部分后台HTTP路径依赖这个外层边界；`X-Site-Sync-Intent` 和自填身份头不能作为互联网身份认证。

不要把运行中的Site改成公开/共享，也不要把此bundle直接部署到无额外鉴权的公开workers.dev或其他平台。公开GitHub仓库不等于公开健康站点。多用户、多租户、自托管和公网站点不在当前支持范围。

## 认证内容

仅由所有者在Sites Secrets界面填写MI_USER_ID、MI_PASS_TOKEN。不要提交`.env`、本地登录配置、Cookie数据库、HAR、成功认证响应、数据库导出或请求日志。

服务Token、ssecurity、STS票据、FDS下载签名URL、FDS AES密钥仅在后端内存中使用，不能输出到聊天、日志、源码或D1。解密后的健康文件可以存私有D1；密钥与认证响应不能存。日志只输出固定错误码和必要计数，不输出原始异常堆栈或外部响应体。

账号被要求验证码/二次验证时停止，不绕过。Token可被小米撤销；不要把通用浏览器登录态当作健康服务认证成功。不要向他人提供自己的Secret来“复现”。

## 本公开仓库包含什么

- TypeScript源码、空库SQL、完整第三方许可证、合成测试、复现文档。
- 无生产数据库、真实健康样本、私人站点链接/ID、账号或设备标识、任何原实例Git历史。
- 已将原实现中源自真实案例的部分测试数字/时间替换为合成值；测试中的`synthetic`、`NEVER-RETURN`等均为哨兵，不是可用凭据。
- 保留实现中的已知限制，不将脱敏导出描述成完成了新的数据覆盖开发。

如发现潜在凭据泄露，不要在公开issue粘贴Secret、健康记录或完整日志；先撤销/更新对应凭据，再通过适当的私密通道报告。
